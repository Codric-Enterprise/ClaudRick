Each agent is an employee with one job. Describe the specialist you need in plain English.

3 QA sub-agent

The 5-Part Prompt Formula

Structure every complex prompt with these 5 elements. Works with any model, any task.

The Full Prompt Template
1
The Reason — why you're asking. "I'm working on [X] for [who]. They need [what the output enables]."
2
The Goal — the outcome, not the steps. "Goal: [outcome]. Here's everything I know: [context]."
3
The Interview — you have what's missing. "Before you start, ask me everything you need to get this right."
4
The Boundary — what it may and may not touch. "Do the simplest thing that works. Only pause for me on irreversible actions."
5
The Proof — kills the fake "all done!" "Only report work you can point to evidence for. Lead with the outcome."
"I'm working on [X] for [who]. Goal: [outcome]. Here's what I know: [context]. Before you start, ask me what you need. Do the simplest thing that works, pause only on irreversible actions. Report only what you can prove, outcome first."click to copy

The Chain — One Pipeline, Any Task

Six single-purpose commands, run in sequence, turn into one compounding instrument: rigor sets the ground rules, brainstorm opens the field, evaluate narrows it, details fill it in, edit sharpens it, and a verification gate catches what's still unproven before you call it done. Run all six on anything — a plan, a draft, a decision, a piece of code — and the output is categorically better than any single step alone.

1. Rigor power-practices

Set the ground rules before a single idea gets generated: right model for the difficulty, verify instead of guess, no fabricated links or numbers, and the goal is a real deliverable — not a description of one.

Before starting: pick the model that matches this task's difficulty, verify any fact you're not certain of instead of guessing, flag anything you can't confirm, and plan to hand back the actual deliverable — not a summary of what it would contain.click to copy

2. Brainstorm /brainstorm

Go wide before going deep. A handful of unconventional options surfaces the ones nobody would reach by narrowing early.

Brainstorm a wide range of options for [task], including a few unconventional ones. Cluster them into themes, then flag the 3 most promising with a one-line reason each.click to copy

3. Evaluate /evaluate

Score the shortlist against criteria you actually state, so the pick is traceable instead of a vibe.

Evaluate the top 3 against [criteria — e.g. cost, speed, risk, reversibility]. Score each 1-5 per criterion, show the math, and recommend one with the tradeoff you're accepting.click to copy

4. Detail /details

Turn the winning option from a concept into something buildable — real numbers, real steps, real names.

Expand the winning option with concrete detail: specific numbers, ordered steps, named tools/files/people. No filler, no "as needed," no vague qualifiers.click to copy

5. Edit /edit

Cut everything that isn't earning its place — hedging, redundancy, passive voice — without losing what it actually says.

Edit this for concision: cut hedge words, redundant phrases, and passive voice. Keep every fact and the original meaning intact. Shorter is only better if nothing true is lost.click to copy

6. Verify test-and-lint

The same gate CI runs on code — checks, lint, tests — generalized to any deliverable: run it, break it, and say exactly what you checked before calling it done.

Before calling this done: what would break it, and did you check? List exactly what you verified — ran it, tested it, confirmed the number — versus what's still unproven. Don't report "done" without evidence.click to copy
