argument-hint: [project or feature to estimate]

Produce a realistic project estimate:

1. **Scope decomposition** — break into work packages, each estimable independently
2. **Three-point estimates** — for each package: optimistic, likely, pessimistic (with reasoning)
3. **Risk-adjusted total** — weighted estimate using PERT formula
4. **Confidence interval** — 50th, 75th, and 90th percentile completion dates
5. **Assumptions log** — everything you assumed; if any are wrong, which estimates change
6. **Dependencies & blockers** — external factors that could delay, with lead times
7. **Hidden work** — testing, deployment, documentation, code review, meetings, bug fixes (the work people forget to estimate)
8. **Team factors** — ramp-up time, context switching, availability, skill gaps
9. **Historical comparison** — does this estimate pass the smell test against similar past projects?
10. **Communication format** — present to stakeholders as a range, not a single number, with the key risk factors
